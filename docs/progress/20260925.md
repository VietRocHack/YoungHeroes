# 2026-09-25

## 10:17 — Abuse prevention (ADR 0006), Live out of beta

Locked down the public Gemini-backed backend. Details and reasoning are in
`docs/adr/0006-abuse-prevention.md`.

- **Deploy caps:** `--max-instances=3 --concurrency=20 --timeout=300` added
  to both `scripts/deploy.sh` and `.github/workflows/deploy.yml`.
- **Call IDs are now tickets:** only recently issued (10 min), unfinished
  IDs are honored. A Live session can be claimed once per ID (Firestore
  transaction), and the classic flow is capped at 10 turns per call.
- **Live WebSocket:** `Origin` allow-list checked before `accept()`, a 240s
  cap per call, a 30s idle cutoff, and a limit on frame size.
- **Classic endpoints:** `/api/tts` text ≤ 500 chars; `/api/stt` needs
  `callId` (form field, and the frontend now sends it) and caps uploads at 2MB.
  `PracticeCallClassic.jsx` fetches a fresh call ID every time instead of
  reusing one from `localStorage`.
- **`/api/new_call` rate limits:** 20/hour per IP and 300/hour globally,
  kept as Firestore counters in a new `rateLimits` collection.
- **App Check (built, not enforced):** `frontend/src/lib/appCheck.js` sends
  limited-use tokens once `VITE_*` vars are set. The backend verifies them
  with `consume=True` once `APP_CHECK_ENFORCE=true`. Setup steps are in
  `docs/runbook.md` → "Abuse prevention". New deps: `firebase`
  (frontend) and `firebase-admin` (backend).
- The toggle label changed from "Live (Beta)" to "Live".
- Added a `backend` entry to `.claude/launch.json`.

**Verified locally:** a TestClient script against real Firestore and
Gemini ran 16/16 checks: per-IP limit returns 429 on the 4th call,
bad/missing origin and unknown or reused call IDs are rejected, a valid Live
call streams greeting audio and is ended by the server after going idle,
tts/stt reject unknown, finished and oversized requests while a fresh call
still returns audio, and App Check returns 401 for missing or bogus tokens when
enforced. In the browser, Classic got a call ID through Vite, and the Live
socket was accepted through the Vite proxy (the mic is blocked in the
preview pane, so no audio was exchanged). The frontend build is clean.

The local test runs also added about 5 calls to this hour's shared `global`
counter in the prod Firestore database. That's harmless.

## 10:30 — Fix failed deploy (dependency conflict)

The first deploy of the change above failed at the container build.
`firebase-admin==7.7.0` needs `google-cloud-firestore>=2.21`, but it was
pinned to 2.19.0. Local testing missed it because installing firebase-admin
into the venv silently upgraded Firestore to 2.27.0. Pinned 2.27.0 (the
version the local checks ran on). The live site kept serving the previous
build, still labeled "Live (Beta)", until this redeploy.
