# 2026-09-24

## Session 1 — new Gemini key, mobile bugs, universal back button, image style, Live API ADR

Continuing from 2026-09-23's billing fix.

- User created a fresh Gemini key ("Young Heroes") via the AI Studio UI.
  Pushed it to the `youngheroes-gemini-api-key` Secret Manager secret and
  redeployed Cloud Run — verified the full dispatcher+TTS path live
  (`/api/tts` returns real `audio/wav`). Along the way, piping the key
  through `gcloud ... | gcloud secrets versions add` baked in a trailing
  `\r\n` that broke it as an HTTP header once deployed
  (`requests.exceptions.InvalidHeader`) — fixed by stripping with
  `tr -d '\r\n'` before writing the next secret version.
- Ran `generate_quiz_assets.py` for real for the first time — found the 23
  generated files were actually JPEG bytes saved with a `.png` extension
  (Gemini's image model returns `image/jpeg` regardless of filename), so
  Firebase Hosting served them with a `Content-Type: image/png` header over
  real JPEG data. Renamed all 23 to `.jpg` and updated every reference
  (`quiz.py`, `SkillsRecognize.jsx`, `SkillsCommunicate.jsx`).
- Fixed a hover bug on SkillsRecognize's "Call 911" button: its decorative
  `star.png`/`learnRec1.png` images were children of `MotionButton`, and a
  CSS `transform` (the hover scale) makes its element the containing block
  for absolutely-positioned descendants — so hovering yanked the decorations
  to a new position. Moved them to be siblings instead.
- **Real mobile device testing** (via the user's phone, not just viewport
  emulation) surfaced two more bugs invisible to browser-pane automation:
  content clipping and janky page-transition "flashing." Root causes:
  - `PhoneFrame` always rendered a fixed-size (`min(400px,100%) x
    min(812px,100dvh)`), `overflow-hidden` "phone simulation" card, which is
    pointless and actively harmful on an actual phone — taller content was
    being clipped instead of scrolling. Now full-bleed with natural scroll
    below the `sm:` breakpoint; desktop/tablet keep the simulated-phone card
    unchanged.
  - Every route change ran two independently-timed animations at once —
    `PageTransition`'s own fade+slide (added earlier this week for
    direction-aware back/forward transitions) and `PhoneFrame`'s own
    fade+slide-up. Removed `PageTransition` entirely (its POP-vs-PUSH
    direction heuristic didn't hold up against real navigation history
    either) and kept only `PhoneFrame`'s simpler, already-proven animation.
  - Also: `Footer` was `hidden sm:flex` on the assumption mobile wouldn't
    have room for it under the old card layout — no longer true, now shown
    on every screen size.
- **Added a universal `BackButton` component** — a small circular icon
  button pinned to the screen's top-left, used identically on every page
  that needs back navigation (`Practice`, `PracticeDecision`, `Skills`,
  `SkillsRecognize`, `SkillsCommunicate`). Replaced each page's own bespoke
  "Cancel" pill / "Back" pill / illustrated "Back" tile with it.
  `PracticeCall` (active call state) and the `*Result` screens (already have
  a "Home" button) deliberately don't get one.
- Added a small text label under each icon in the Communicate quiz's option
  grid (icons alone didn't say what they represented) and made the whole
  card — not just the icon — tappable.
- **Rewrote the quiz image style guide.** All 23 images had been generated
  independently with one loose text prompt and came back in visibly
  different art styles. New approach: anchor every generation to the app's
  existing `teamwork.png` illustration style (thin black outlines, minimal
  flat fill, one mint-teal accent, dot eyes) by (1) writing that style out
  explicitly, split into a `SCENE_STYLE_PREFIX` (recognize quiz — allows
  naturalistic orange/red flame and gray smoke for hazard recognition) and
  `ICON_STYLE_PREFIX` (communicate quiz — strict white/cream + teal only),
  and (2) passing `teamwork.png` itself as a reference image alongside the
  text prompt on every generation call, since text description alone wasn't
  holding style consistent across independent calls. Regenerated all 23 —
  result is visibly consistent with each other and with the rest of the app.
- **Researched Gemini's Live API** per the user's question about making the
  voice call feel like natural conversation instead of stop-to-record. Wrote
  up `docs/adr/0005-live-api-for-voice-call.md` (status: Proposed) with full
  context, the decision (server-to-server WebSocket architecture, tool-call
  based `end_call` signal replacing the JSON-schema `isFinished`/
  `isPrankCall` fields), consequences, and an 8-step migration plan. Not yet
  implemented — this is a genuinely bigger rewrite than it looks (audio
  capture has to move off `MediaRecorder` entirely to get raw PCM, and it
  cuts against part of the reasoning in ADR 0004).
