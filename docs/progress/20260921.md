## Session 2 — switch the frontend from Next.js to Vite

Mid-migration, the user asked to move the frontend off Next.js onto Vite —
the original hackathon repo had a leftover `vite.svg`/Vite-template CSS that
turned out to signal the intended tooling, not dead cruft as first assessed.

- Rewrote `frontend/` as a React 19 + Vite SPA: `react-router-dom` replaces
  Next's App Router (`next/navigation`'s `useRouter` → `useNavigate`), a root
  `index.html` + `src/main.jsx` replace `layout.jsx`'s metadata/head, pages
  moved from `src/app/**/page.jsx` to flat `src/pages/*.jsx`, `vite.config.js`
  replaces `next.config.js` (dev-only `/api` proxy via `server.proxy` instead
  of `rewrites()`). `firebase.json`'s Hosting `public` dir updated to
  `frontend/dist` (Vite's build output) from the old `frontend/out`.
- Found and fixed a real bug introduced during the earlier animation pass:
  Framer Motion's `whileHover`/`whileTap` scale animations write their own
  inline `transform`, which was silently overwriting Tailwind's
  `-translate-x-1/2`/`-translate-y-1/2` centering utility on a few
  absolutely-positioned buttons (the practice/skills menu buttons, and the
  big red call button on `practice/decision`), knocking them off-center.
  Fixed by keeping the plain (non-motion) element responsible for
  position/centering and nesting the motion element inside it purely for the
  scale animation — verified visually in the browser at both mobile and
  desktop widths after the fix.
- Verified end-to-end in the browser (no backend/Gemini key yet, so voice
  call and generated images aren't live): full click-through of
  `skills/communicate` (Continue correctly disabled until a selection is
  made, result screen recaps real answers) and `skills/recognize` (heart
  count decrements on a wrong answer, result screen shows real stars/hearts
  and correctly hides "You kept calm!" once a mistake was made). Lint and
  build both clean.
